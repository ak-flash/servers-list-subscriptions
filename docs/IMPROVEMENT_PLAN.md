# План улучшений проекта servers-list-subscriptions

Дата анализа: 2026-10-18

## Фаза 1 — Критичные проблемы безопасности (в первую очередь)

### 1.1 Хеширование паролей [ВЫПОЛНЕНО]
- **Проблема:** пароли админов хранятся и сравниваются в открытом виде (`src/index.js:108, 254-258, 470-471`).
- **Решение:** реализован scrypt (`src/utils/passwords.js`); legacy-пароли автоматически мигрируют при успешном входе.

### 1.2 Убрать дефолтные секреты [ВЫПОЛНЕНО]
- **Проблема:** захардкожен `SESSION_SECRET` fallback `'vpn-subscription-secret-key-2024'` (`src/index.js:41`) и дефолтный пароль `admin123` (`src/index.js:471`).
- **Решение:** в production запуск завершается без `SESSION_SECRET`; `ADMIN_PASSWORD` обязателен для создания администратора; добавлен `WEBHOOK_SECRET`.

### 1.3 Rate limiting [ВЫПОЛНЕНО]
- **Проблема:** `/admin/login` допускает неограниченный перебор паролей (`src/index.js:106`); публичный `/join/:id` тоже не ограничен, каждый запрос пишет в БД.
- **Решение:** добавлены in-memory лимиты по IP: 10 попыток входа за 15 минут и 120 запросов подписки за минуту.

### 1.4 CSRF на все mutating-маршруты [ВЫПОЛНЕНО]
- **Проблема:** `csrfToken`/`requireCsrf` применены только в `routes/subscriptionSources.js`; формы серверов, пользователей, `/admin/stats/clear`, webhook без защиты (`src/index.js:162-272, 632`).
- **Решение:** токен добавлен в admin-формы и `requireCsrf` подключён ко всем изменяющим admin/API-маршрутам.

### 1.5 Аутентификация API/webhook [ВЫПОЛНЕНО]
- **Проблема:** `POST /api/traffic/report` (`src/index.js:302`) и `POST /api/webhook/traffic` (`src/index.js:358`) без аутентификации — подделка статистики трафика.
- **Решение:** добавлена аутентификация через секретный сегмент URL: `/api/webhook/traffic/<WEBHOOK_SECRET>` и `/api/traffic/report/<WEBHOOK_SECRET>`.

### 1.6 Доверие к прокси-заголовкам
- **Проблема:** `x-forwarded-for` используется без настройки `trust proxy` — подделка IP в логах (`src/index.js:88`).
- **Решение:** использовать `req.ip` с явной настройкой `app.set('trust proxy', ...)`.

## Фаза 2 — Надёжность данных

### 2.1 Оптимизация сохранения БД
- **Проблема:** `saveDb()` экспортирует и fsync-ит всю БД на каждую запись (`src/db/connection.js:104`) — O(n) дисковых операций на каждый запрос подписки/отчёт трафика.
- **Решение:** отложено: требует отдельной переработки API persistence, чтобы не потерять гарантию восстановления после сбоя.

### 2.2 Graceful shutdown и обработка фатальных ошибок [ВЫПОЛНЕНО]
- **Проблема:** нет обработчиков `uncaughtException`/`unhandledRejection` — внезапный exit без `saveDb` (`src/index.js:646`).
- **Решение:** добавлены обработчики с логированием, остановкой scheduler'а и финальным сохранением БД; устранён TDZ-риск monthlyReset.

### 2.3 Ограничение буфера результатов probe [ВЫПОЛНЕНО]
- **Проблема:** при ошибке записи результаты копятся в `this.results` без лимита — рост памяти при сбое диска (`src/services/probeScheduler.js:192`).
- **Решение:** добавлен лимит буфера 1000 записей с удалением старых результатов.

### 2.4 Устойчивость lock-файла [ВЫПОЛНЕНО]
- **Проблема:** `JSON.parse` lock-файла без try/catch — битый lock ломает запуск (`src/db/connection.js:24`).
- **Решение:** битый lock-файл теперь удаляется и блокировка повторяется.

### 2.5 Надёжный месячный сброс статистики [ВЫПОЛНЕНО]
- **Проблема:** `checkMonthlyReset` срабатывает только если процесс жив в 00:00 1-го числа (`src/index.js:512`).
- **Решение:** добавлена миграция `004-app-state`; дата сброса хранится в БД, повторный сброс исключён.

### 2.6 Ротация бэкапов
- **Проблема:** только один бэкап в день, без ротации (`src/db/connection.js:48`).
- **Решение:** хранить N последних бэкапов (например, 7), удалять старые.

### 2.7 Реальная отмена HTTP-запросов
- **Проблема:** `abortable` в safeHttp не отменяет внутренний запрос — работа продолжается после abort (`src/utils/safeHttp.js:43`).
- **Решение:** пробрасывать signal в `http.request`/`destroy` сокета.

## Фаза 3 — Усиление безопасности (средний приоритет)

### 3.1 Защита сессий
- `req.session.regenerate()` после логина (защита от фиксации сессии, `src/index.js:110-113`).
- `cookie.secure: true` в production; вынести session store из MemoryStore в SQLite/файл (`src/index.js:40-44`).

### 3.2 Security-заголовки
- Добавить CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` (helmet или вручную).
- Убрать внешний CDN Tailwind со страницы QR (`src/views/partials/subscription-head.ejs:6`) — утечка Referer со ссылкой подписки третьей стороне.

### 3.3 Валидация конфигурации
- Валидировать `PUBLIC_DOMAIN` при старте (используется в ссылках подписок, `src/routes/subscriptions.js:25-29`).
- Валидация всех env-переменных из `.env.example` при старте с понятными ошибками.

## Фаза 4 — Архитектура

### 4.1 Разделение монолита
- **Проблема:** `src/index.js` — 653 строки: app, роуты, статистика, lifecycle в одном файле.
- **Решение:** вынести admin-роуты в `src/routes/admin*.js`, lifecycle (shutdown/reset) в отдельный модуль.

### 4.2 Фабрика приложения
- **Проблема:** глобальные синглтоны создаются при require (`src/index.js:29`).
- **Решение:** `createApp(config)` — для изоляции и тестируемости.

## Фаза 5 — Тестирование

- **Проблема:** 24 теста только на db/парсер/scheduler; нет тестов HTTP-роутов, админки, auth, CSRF (`test/*.test.js`).
- **Решение:** добавлен `test/password.test.js`; HTTP-тесты обновлены для CSRF и хешированных паролей. Полное покрытие admin/webhook и shutdown — отложено.

## Фаза 6 — DevOps

- **CI:** нет автоматического запуска тестов — добавить GitHub Actions workflow (`npm test` на push/PR).
- **Docker:** отсутствует Dockerfile для воспроизводимого деплоя.
- **Логирование:** структурированные логи (уровни, JSON) вместо console.log.
